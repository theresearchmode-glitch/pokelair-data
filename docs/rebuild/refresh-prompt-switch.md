Daily data refresh for the NastyPlot artifact https://claude.ai/artifact/5VBfLTR5sM4JU5NswJYyGk (owned by this account). Base URL: https://raw.githubusercontent.com/theresearchmode-glitch/pokelair-data/live/out/
Page storage limit (Nov 10): one artifact document can hold at most 262,144 bytes. The data job splits any document over 200,000 bytes into two parts in out/split/ (nothing is dropped; the page joins the parts back, matching their "_part" stamps). Always use those parts for split documents, never the whole file.
1) Download out/limitless.json. If its "updated" date is more than 2 days old, wait 20 minutes and download again once; if still old, stop and report it (it means the live branch has not moved: the daily tests have been failing; say so). Also download out/split/index.json; its "split" object names the documents that come in two parts (for example results, model, events). If it is missing, treat nothing as split.
2) Using the ArtifactData tool on that artifact: if "results" is split, set meta/results to out/split/results.json and meta/results_2 to out/split/results_2.json, each exactly as is; otherwise set meta/results to limitless.json's "results" object exactly as is. Then update (merge, don't replace) meta/perf with {adj: the file's "adj" object, updated: today's date YYYY-MM-DD}. Also download out/perf.json; if it downloads and parses, add to that same meta/perf merge EVERY top-level key of perf.json except "updated" (today these are tour, ingame, smogon, ladder, outside, reg and possibly official), each exactly as is — but skip "tour" if it has fewer than 50 rows and "ingame" if it has fewer than 50 names. If meta/perf still holds a "prd" key or an "official" key that perf.json no longer has, remove them in the same update (write them as {"__delete__": true}). Each part carries its own "updated" date; do not change them. If perf.json is missing or fails to parse, skip it and say so at the end. Writes to existing documents need if_version: read each document first (get) and pass its version. Save each payload to a local JSON file and pass file_path rather than inline data.
3) Also download out/meta_tour.json, out/teams.json, out/history.json, out/model.json, out/meta_ladder.json, out/meta_ingame.json, out/events.json, out/track.json, out/practice.json, out/weekly.json, out/calendar.json, out/post.json and out/info.json. For each one that downloads and parses: set meta/doubles_tour to meta_tour.json, meta/teams to teams.json, meta/history to history.json, meta/model to model.json, meta/doubles to meta_ladder.json, meta/doubles_ingame to meta_ingame.json, meta/events to events.json, meta/track to track.json, meta/practice to practice.json, meta/weekly to weekly.json, meta/calendar to calendar.json, meta/post to post.json (the News and Mystery Gifts list) and meta/info to info.json (who runs each move, item and Ability), each exactly as is — except that for a document the split index names (by its page name: results, doubles_tour, teams, history, model, doubles, doubles_ingame, events, track, practice, weekly, calendar, post, info), set meta/<name> to out/split/<name>.json and meta/<name>_2 to out/split/<name>_2.json instead. For every one of those page names that is NOT split today, if a meta/<name>_2 document exists, delete it. Skip any file that is missing or fails to parse. Do not touch any other documents. Batches of up to 50 writes are fine (keep each batch under 1 MiB; split if needed). If a write is refused, keep going with the others, then report exactly which document, its size in bytes and the reason.
4) Always do this read-back, even if some writes failed: confirm meta/results (joined with meta/results_2 when split) has 100+ proven teams, 100+ cores and a "records" array; meta/perf adj.rows has 200+ rows (and, if written today, tour.rows 50+ and ingame.names 50+) and a "reg" object; list which other perf parts (smogon, ladder, outside, official) are present with their "updated" dates; meta/doubles_tour has 40+ rows in top; meta/teams has teams; meta/model has "ships" and "eval" (in either part); meta/doubles and meta/doubles_ingame have rows in top; meta/events has 10+ events and a dict array (counting both parts); meta/practice, meta/weekly, meta/calendar and meta/track exist; meta/post has a "news" array with 1+ items and a "gifts" array (if out/post.json was missing or failed to parse, say so: the page then shows its built-in list); meta/info has a number "N" and the objects "mv", "it" and "ab" (if out/info.json was missing, say so: the info sheets then show no "who runs it" counts); and for each split document, both parts carry the same _part.id.
5) Also download out/crosscheck.json if present and report how many Pokémon (or events) each comparison flagged, and out/official_compare.json if present (official events: Victory Road vs the previous file / Liquipedia).
6) Finish with one short summary: teams, games, tournaments and date range from limitless.json; which documents were written in two parts (from the split index, with their sizes); which perf parts were merged and their dates; the active regulation from perf.json reg (and whether a newer one was seen); model.json's ships value plus eval.model_teams_only.acc vs eval.raw_win_rates.acc; how many news items and gifts meta/post holds and post.json's "ran" date (when the news feed last ran; say "no ran date" if it has none); meta/info's N and period; the cross-check flag counts. If anything fails, say exactly what failed.
```
