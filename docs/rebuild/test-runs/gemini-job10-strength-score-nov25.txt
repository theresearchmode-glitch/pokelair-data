needs targeted bug fixes (architecture is solid and well-validated on held-out games, with 6 real code bugs found — 1 CRASH, 3 WRONG-SCORE, 1 WRONG-ADVICE, 1 SLOW — plus 2 unseen dependencies marked not checked):
- CRASH: `CH.wordOf(NaN)` throws `TypeError` because `CH.WORDS.find(w => NaN >= w[0])` returns `undefined`.
- WRONG-SCORE (3): (a) Duplicate species (Species Clause) makes `CH.strengthOf` return `null`, so `CH.gradeOf` falls back to v1 with `illegal: false`; (b) `89.6` rounds to `90` in `CH.gradeNum` / `CH.whyData` while `CH.grade(89.6)` is `'B'` (`90 · Tournament ready`); (c) empty `META.model.monSd: {}` causes `Math.max()` -> `-Infinity` -> `CH.sdOf` returns `Infinity` (`swapSure` also affected); plus `gradeMemo` omits `m.itemDefault`.
- WRONG-ADVICE: `LANE.of` tags a `reach` fix as rank-0 `fix` even when `planGrade(pl) < gBase`, potentially promoting a score-lowering swap to Suggestion #1.
- SLOW: `CH.strengthOf` and `CH.partialOf` call `strengthX(names, ms)` solely for `xs.x0`, but `strengthX` runs `structCredit(ms)` (`proChecks` + `gamePlan` + `trPlan` + `deadItems`) on every call and throws `xs.sc` away.

All 3 diffs below fix only code bugs (zero constant tuning, zero design/copy changes) and are verified with Node VM before/after S3 proofs. `experiments/strength-invariants.mjs` is syntax-checked (`node --check` -> OK); browser execution is `not run` (no `app/dist/page.html` or Playwright in VM).
