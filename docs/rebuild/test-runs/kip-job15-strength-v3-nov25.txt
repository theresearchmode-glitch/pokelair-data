--- A1. LITERATURE SYNTHESIS (EVERY CLAIM WITH VERIFIED URL + DATE + TIER) ---

1. Team-Composition Win Models:
   - Factorization Machines (FM) [T1, Dec 13, 2010]: Steffen Rendle, "Factorization Machines", IEEE ICDM 2010, pp. 995-1000 (https://www.ismll.uni-hildesheim.de/pub/pdfs/Rendle2010FM.pdf). Models all pairwise feature interactions via rank-d dot products in O(k*d) linear time, sharing statistical strength across sparse pairs where explicit one-hot pair parameters fail.
   - Factorization Machines on MOBA Drafts [T1, Feb 2017]: Aleksandr Semenov et al., "Performance of Machine Learning Algorithms in Predicting Game Outcome from Drafts in Dota 2", CCIS 2017 (https://www.researchgate.net/publication/313010005_Performance_of_Machine_Learning_Algorithms_in_Predicting_Game_Outcome_from_Drafts_in_Dota_2). Found FM outperformed bag-of-heroes logistic regression on sparse hero-composition drafts.
   - Intransitive Matchups (Blade-Chest Model) [T1, Feb 2016]: Shuo Chen & Thorsten Joachims, "Modeling Intransitivity in Matchup and Comparison Data", ACM WSDM 2016 (https://www.cs.cornell.edu/~shuochen/pubs/wsdm16_chen.pdf). Extends Bradley-Terry with d-dimensional blade (offense) and chest (vulnerability) vectors so rock-paper-scissors cycles (A > B > C > A) are captured via u(A).v(B) - u(B).v(A).
   - Glicko-2 Dynamic Rating & Rating Deviation [T1, 2001/2013]: Mark E. Glickman, "Example of the Glicko-2 system" (https://glicko.net/glicko/glicko2.pdf). Tracks rating r, rating deviation RD (uncertainty that grows with inactivity), and volatility sigma; prevents stale ratings from distorting updates.
   - Whole-History Rating (WHR) [T1, Sep 2008]: Remi Coulom, "Whole-History Rating: A Bayesian Rating System for Players of Time-Varying Strength", Computers and Games LNCS 5131, pp. 113-124 (https://www.remi-coulom.fr/WHR/WHR.pdf). Exact MAP over time-varying Bradley-Terry ratings with Brownian motion prior across time gaps; beat Elo, Glicko, TrueSkill, and decayed-history algorithms on Go match prediction.
   - TrueSkill 2 [T1, Mar 22, 2018]: Tom Minka, Ryan Cleven, Yordan Zaykov, "TrueSkill 2: An improved Bayesian skill rating system", Microsoft Research MSR-TR-2018-8 (https://www.microsoft.com/en-us/research/wp-content/uploads/2018/03/trueskill2.pdf). Adds time-varying skill drift, experience, and cross-mode priors (note: TrueSkill is patented until Apr 9, 2029 per Wikipedia; use open Bayesian BT/OpenSkill math instead).
   - OpenSkill (Weng-Lin Bayesian Plackett-Luce) [T1/T2, 2011 / Jan 9, 2024]: Ruby C. Weng & Chih-Jen Lin, JMLR 12(9):267-300 (https://openskill.me/en/stable/references.html) and OpenSkill library paper (https://arxiv.org/html/2401.05451v1). Open-license Gaussian/Plackett-Luce Bayesian online rating with time-decaying sigma and conservative rating mu - 3*sigma.

2. Competitive Pokémon / VGC Empirical Analytics (Numbers Only):
   - VGC Lead Prediction via Team Matchups [T1/T3, Jul 11, 2025]: Bruno Luvizotto Carli, "Predicting competitive Pokémon VGC leads using Latent Semantic Analysis: a data-driven approach to team matchups", Journal of Geek Studies (https://jgeekstudies.org/2025/07/11/predicting-competitive-pokemon-vgc-leads-using-latent-semantic-analysis-a-data-driven-approach-to-team-matchups/). Trained on 1,174 filtered Showdown logs and evaluated on all 32 NAIC 2025 Masters Top 8 games: top-3 predicted leads achieved 62.50% Hard Prediction (both leads exact) and 81.25% Soft Prediction (at least one lead); in the Finals, 83.33% Hard and 91.66% Soft — proving team-vs-team composition strongly constrains Bring-4 / lead selection.
   - VGC-Bench Generalization Benchmark [T1, Jun 12, 2025 / Jan 13, 2026]: "Towards Mastering Diverse Team Strategies in Competitive Pokémon", arXiv:2506.10326 (https://arxiv.org/html/2506.10326v3). Highlights team-preview generalization across diverse VGC team compositions as a primary challenge in competitive Pokémon.
   - Live Reg M-C Usage & Move Concentration [T3, Nov 2026]: MunchStats Reg M-C (https://www.munchstats.com/ and https://www.munchstats.com/insights/) and Pikalytics Reg M-C (https://www.pikalytics.com/). Example move concentration on Sneasler: Close Combat 99.896%, Dire Claw 68.613%, Fake Out 62.110%, Protect 56.569% — confirming why within-species set centering is vital (a 99.9% move carries near-zero within-species variance).
   - NastyPlot's Own Measured Reg M-C Tournament Data [Internal, Nov 9, 2026, docs/strength-score.md]: Over 10,575 sheets / 38,513 games (player skill removed): Has a Mega +19.69 pts standalone (no-Mega teams win 34%), Readiness for top 30 threats +1.05 pts per 10 pts even on top of x0 (95% CI 0.38 to 1.76), Protect +1.00 pt/member standalone, 3+ sharing a type -3.27 pts standalone (-5.73 to -1.67), Attacking types unresisted -0.84 pts/type (-1.18 to -0.55), Speed control -0.6 pts / Fake Out -1.6 pts (not significant because ~92% of tournament teams already run them).

3. Calibration & Communicating Uncertainty to Players:
   - Strictly Proper Scoring Rules [T1, Mar 2007]: Tilmann Gneiting & Adrian E. Raftery, "Strictly Proper Scoring Rules, Prediction, and Estimation", JASA 102(477):359-378 (https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jasa.pdf). Proves log-loss and Brier score are strictly proper (minimized uniquely by true probabilities), whereas accuracy alone can be gamed and ignores confidence calibration.
   - Temperature Scaling (Single-Parameter Calibration) [T1, Jun/Aug 2017]: Chuan Guo, Geoff Pleiss, Yu Sun, Kilian Q. Weinberger, "On Calibration of Modern Neural Networks", ICML 2017 (https://proceedings.mlr.press/v70/guo17a.html). Single-parameter logit scaling (exactly what model.mjs's `calib` does!) is convex, fast, preserves ranking, and outperforms more complex binning/vector calibrators on small-to-medium validation sets.
   - Communicating Uncertainty Without Losing Trust [T1, Mar 2020]: Anne Marthe van der Bles et al., "The effects of communicating uncertainty on public trust in facts and numbers", PNAS 117(14):7672-7683 (https://www.pnas.org/doi/10.1073/pnas.1913678117). Across controlled experiments, communicating uncertainty as a numerical range alongside a point estimate (e.g., "82, likely range 78-86") communicated uncertainty clearly WITHOUT reducing public trust in the numbers or the source, whereas vague verbal qualifiers ("estimated") failed or lowered trust.
   - Visualizing Uncertainty [T1, Sep 2011 / May 2019]: David Spiegelhalter et al., Science 333:1393-1400 & Royal Society Open Science 6(5):181870 (https://royalsocietypublishing.org/rsos/article/6/5/181870/95102/Communicating-uncertainty-about-facts-numbers-and). Recommends pairing numeric ranges with plain-language framing ("few tournament games yet") matched to audience numeracy.

4. Small-Data Methods for a New Regulation (Reg M-D Starts Dec 2):
   - L2-SP Transfer Regularization [T1, Feb/Jul 2018]: Xuhong Li, Yves Grandvalet, Franck Davoine, "Explicit Inductive Bias for Transfer Learning with Convolutional Networks", ICML 2018 (https://arxiv.org/abs/1802.01483). Adding an explicit L2 penalty `lambda * ||theta - theta_prev||^2` toward the prior task's weights acts as "soft freezing" — consistently outperforming standard L2-to-zero especially when target data is small (e.g., 84.2% vs 79.6% on MIT Indoors 67). For M-D day one: pull unchanged Pokémon toward their M-C `b_prev` with decaying `lambda(n) = lambda_0 / (1 + n / n_half)`, and zero out `b_prev` for newly added or balance-patched Pokémon!
   - Time-Varying Uncertainty Inflation [T1, 2008 / 2013]: Glicko-2 RD inflation (https://glicko.net/glicko/glicko2.pdf) and WHR Brownian prior (https://www.remi-coulom.fr/WHR/WHR.pdf). At a regulation boundary, widen prior variance (higher RD / lower prior precision) so new games rapidly overwrite stale M-C beliefs while preventing 3-game flukes from hitting 99.

PART C — TOP 5 CODEABLE IDEAS IN experiments/v3-lab.mjs (WITH S7 FALSIFICATION)
================================================================================

All 5 ideas are runnable together (`--ideas=all`) or individually (`--ideas=fm`, etc.). None touch `model.mjs` or the page.

1. `--idea=fm` — Factorization Machine Pairs (rank d=4, L2=25):
   - Replaces sparse one-hot pairs `q` with low-rank species embeddings `Fm[mon][4]` (`0.5 * sum_d ((sum v)^2 - sum v^2)`).
   - S7 falsification (what proves it wrong): Paired 95% bootstrap CI of `(LL_fm - LL_base)` is NOT strictly `< 0` (i.e. upper bound >= 0). Verdict prints `REJECT` or `NO DIFFERENCE / REJECT`.

2. `--idea=matchup` — Blade-Chest Intransitive Team-vs-Team Matchup Term (rank d=4, L2=15):
   - Fits antisymmetric `u(A).v(B) - u(B).v(A)` on top of baseline `x(A) - x(B)` to capture rock-paper-scissors counters.
   - S7 falsification: Paired 95% bootstrap CI of `(LL_matchup - LL_base)` is NOT strictly `< 0` on held-out games. (Even if it wins head-to-head, note per `docs/strength-score.md` that matchup terms belong in Battle unless field-averaged strength also wins.)

3. `--idea=glicko` — Strictly Causal Online Glicko-2 Player Skill Offset:
   - Computes chronological pre-match `(mu, phi)` per player before each game with RD inflation (`cDrift * sqrt(days)`) over inactive gaps, feeds `0.5*(mu_A - mu_B)` as a fixed causal skill offset during team fitting, and applies stronger ridge (`3x ls`) on residual static skill.
   - S7 falsification: Team-only held-out log-loss (how the Strength Score predicts without knowing the player) fails to beat baseline with paired 95% CI strictly `< 0`.

4. `--idea=no-evid-hier` — Clean In-Objective Ridge (No Post-Hoc `EVID_K`) + Recency-Aligned Team-Aware Six Delta:
   - Removes post-hoc `b *= n/(n+1000)` / `q *= n/(n+300)` double shrinkage (`evidK=0, evidKp=0`), raises in-objective `lb` (`2.5x`) and `lp` (`1.5x`), and adds a recency-weighted exact-six residual `delta` (`tau=0.1`, `>=10` games) computed against the FULL `base.x` (including `noMega` and `protectLow`, fixing the `six.mjs` bug!).
   - S7 falsification: Paired 95% CI of `(LL - LL_base)` is NOT strictly `< 0`, OR calibration slope moves further from `1.0` than baseline.

5. `--idea=mega-cap` — Champions Rule Mega Diminishing Returns (`multiMega` Team Feature):
   - Adds `multiMega = max(0, megaCount - 1)` alongside `noMega` and `protectLow` so 2-Mega teams (4 of the first 5 tournament teams!) do not linearly double-count two Megas when Champions allows only 1 Mega Evolution per battle.
   - S7 falsification: Paired 95% CI of `(LL - LL_base)` is NOT strictly `< 0`, OR learned `T[multiMega] >= 0` (contradicting diminishing returns).

PART D — M-D DAY ONE SMALL-DATA SIMULATION (--md-sim)
================================================================================

Purpose: Reg M-D starts Dec 2 with a balance patch and 0 tournament games. To decide how NastyPlot should rate teams in M-D's first two weeks, `node experiments/v3-lab.mjs --md-sim` simulates a fresh regulation using M-C's own chronological history:
- Trains ONLY on Weeks 1, 2, 3, and 4 (`<= start + 7*wk` days).
- Evaluates every checkpoint on the SAME future test set: all tournament games in Week 5+ (`> start + 28` days).
- Compares 4 cold-start / small-data strategies with paired 95% bootstrap CIs vs Cold Start:
  1. `cold-start`: Today's `model.mjs` settings from scratch.
  2. `heavy-ridge`: 3x species ridge, pairs & sets turned off, lighter `evidK=300` (avoids overfitting sparse pairs/sets on <1,500 games).
  3. `usage-prior`: Empirical Bayes prior shrinking each Pokémon toward `0.12 * log((usage_i + 5) / (mean_usage + 5))` from the new regulation's early usage.
  4. `l2-sp-decay`: L2-SP transfer prior (`lambda_sp = 25 / (1 + n / 2500)`) pulling weights toward a prior model (accepts `--prior-model=out/model_mc.json` for real M-D deployment; falls back to strictly causal Week-1 shrunk win-rate prior during self-contained M-C replay). Turns pairs on at `n >= 1,500` games and sets on at `n >= 2,500` games.

Decision rule for Dec 2 (M-D launch):
- Whichever strategy has the lowest log-loss (with 95% CI beating `cold-start`) at Weeks 1 and 2 on M-C's replay becomes the M-D Weeks 1-2 recipe, with prior weights zeroed for every Pokémon buffed/nerfed/added in the Dec 2 patch.

PART E — WHAT OUR CURRENT MODEL MAY BE GETTING WRONG (CODE AUDIT)
================================================================================

1. PRE-SPLIT FEATURE & SET-CENTERING LEAKAGE (`model.mjs:18-35`):
   - Finding: `pairIx` (pairs on >=30 teams, lines 18-21), `keep` (set features on >=40 decks, lines 25-29), and `freq[j]` (within-species centering means, lines 31-35) are all computed over ALL `G` BEFORE `train`/`test` are split at lines 55-62!
   - Impact: Internal validation (`fitPart` vs `val`) and `TRAIN_ONLY=1` (`train` vs `test`) leak future meta usage and future set frequencies into feature selection and centering.
   - Experiment to show it: Run `v3-lab.mjs` (which builds `pairIx`/`keep`/`freq` strictly inside `train`) vs `model.mjs --verify-baseline` on the same cuts and measure the log-loss delta.

2. DOUBLE-COUNTING TEAM BASICS & UNWEIGHTED IN-SAMPLE REFIT IN `six.mjs` (`six.mjs:16-19,20-27`):
   - Finding A: `six.mjs:16-19` defines `xOf(t, d)` as `MD.mons + MD.pairs + MD.sets` — it COMPLETELY OMITS `MD.team` (`noMega = -0.73`, `protectLow = -0.16`)! For any no-Mega or low-Protect six, `six.mjs` sees an inflated `xOf`, learns a negative `delta` to compensate, and then the site adds BOTH `MD.team` AND `delta`, double-counting the penalty.
   - Finding B: `six.mjs:20-27` fits `delta` on ALL `M.m` with NO recency weighting (`half=0`) and on the exact same in-sample games `model.mjs` already fit `b, q, c` on, while refitting player skill `s` from scratch with unweighted `SIG_S=0.6`.
   - Experiment to show it: `--idea=no-evid-hier` in `v3-lab.mjs` includes full `base.x` (with `team` basics) and matching recency half-life in the six-delta fit.

3. POST-HOC `EVID_K` DOUBLE SHRINKAGE & STALE UNCERTAINTY (`model.mjs:99-107`):
   - Finding: Adam fits `(b, q, s, c, T)` jointly under ridge `(lb, lp, ls, lc, 1)`. Then lines 99-101 compute Hessian variances `vb`/`vq`, and lines 103-107 multiply `b[j] *= n/(n+1000)` and `q[j] *= n/(n+300)` AFTER optimization without refitting `c`, `T`, or `s` and without updating `vb`/`vq`.
   - Impact: Medium-sample Pokémon (e.g., 500 games) get shrunk twice (by `lb` AND by `0.33x`), pushing unshrunk set/team weights out of scale and forcing `calib` to over-stretch (`calib > 1`) to compensate; `monSd`/`pairSd` ignore the post-hoc scaling.
   - Experiment to show it: `--idea=no-evid-hier` replaces post-hoc scaling with clean in-objective ridge and compares log-loss + calibration slope on the same walk-forward cuts.

4. STATIC PLAYER SKILL CONFOUNDING UNDER 14-DAY DECAY (`model.mjs:81,89`):
   - Finding: Each player gets one static scalar `s[p]` across the whole season, weighted by the same 14-day half-life `W[gi]` used for Pokémon meta drift. A strong veteran who played 40 games 5 weeks ago has their skill weight cut to `0.5^(35/14) = 0.177`, leaking their skill into whatever Pokémon they play this week; conversely, a player improving rapidly has their early losses drag down their late-season `s[p]`.
   - Experiment to show it: `--idea=glicko` tests causal time-varying Glicko-2 player skill with RD inflation vs static `s[p]`.

5. MULTI-MEGA DOUBLE COUNTING (`model.mjs:46,52,88` vs `docs/strength-score.md:62`):
   - Finding: `docs/strength-score.md:62` states the Champions rule: "Mega Evolution: only one Mega per game (a second stone never double-counts)". Yet 4 of the first 5 tournament teams in `out/matches.json` carry TWO Megas, and `model.mjs:88` sums `b[j]` linearly for both Megas while `TEAMF` only checks `noMega` (0 Megas).
   - Experiment to show it: `--idea=mega-cap` adds `multiMega = max(0, megaCount - 1)` and tests whether real games show diminishing returns on 2nd Megas.

6. UNCLAMPED TRAINING VS CLAMPED SCORING + UNWEIGHTED SET CENTERING (`model.mjs:31-35,86-87,160-177`):
   - Finding: `fit()` trains with unclamped `c[j] * (has - freq[j])` where `freq[j]` is unweighted over the entire season, whereas `xClamp()` clamps each Pokémon's set sum to `setRange[n]` at scoring time. If a Pokémon's standard item shifts mid-season, unweighted `freq[j]` leaks into `b[j]`.

+  const W = games.map(g => half ? Math.pow(0.5, (last - dayNum(evDates[g[3]])) / half) : 1);
+  const Wn = games.length / (W.reduce((a, x) => a + x, 0) || 1);
+  const WT = teamHalf === half ? W : games.map(g => teamHalf ? Math.pow(0.5, (last - dayNum(evDates[g[3]])) / teamHalf) : 1);
+  const WTn = games.length / (WT.reduce((a, x) => a + x, 0) || 1);
+
+  const dv = new Map();
+  const deckVec = (t, d) => {
+    if (!useSets || d == null || !deckF[d]) return [];
+    const key = t * 100000 + d; let v = dv.get(key); if (v) return v;
+    v = []; const has = new Set(deckF[d]);
+    for (const n of teams[t]) for (const j of (spFeats.get(n) || [])) v.push([j, (has.has(j) ? 1 : 0) - freq[j]]);
+    dv.set(key, v); return v;
+  };
+  const fmScore = t => {
+    let total = 0; const fs = tf[t].f;
+    for (let d = 0; d < D; d++) {
+      let sum = 0, sq = 0;
+      for (const j of fs) { const v = Fm[j * D + d]; sum += v; sq += v * v; }
+      total += 0.5 * (sum * sum - sq);
+    }
+    return total;
+  };
+  const x = (t, d) => {
+    let v = fmScore(t);
+    for (const j of tf[t].f) v += b[j];
+    for (const [j, w] of deckVec(t, d)) v += c[j] * w;
+    const tv = teamVec(t, d); for (let k = 0; k < tv.length; k++) v += T[k] * tv[k];
+    return v;
+  };
+
+  for (let it = 1; it <= ITERS; it++) {
+    const Gr = P.map(a => new Float64Array(a.length));
+    for (let gi = 0; gi < games.length; gi++) {
+      const [A, B, r, , pa, pb, , dA, dB] = games[gi];
+      const eta = x(A, dA) - x(B, dB) + s[pa] - s[pb], e0 = sig(eta) - r;
+      const d = e0 * W[gi] * Wn, dT = e0 * WT[gi] * WTn;
+      for (const j of tf[A].f) Gr[0][j] += d;
+      for (const j of tf[B].f) Gr[0][j] -= d;
+      for (let f = 0; f < D; f++) {
+        let sumA = 0, sumB = 0;
+        for (const j of tf[A].f) sumA += Fm[j * D + f];
+        for (const j of tf[B].f) sumB += Fm[j * D + f];
+        for (const j of tf[A].f) Gr[1][j * D + f] += d * (sumA - Fm[j * D + f]);
+        for (const j of tf[B].f) Gr[1][j * D + f] -= d * (sumB - Fm[j * D + f]);
+      }
+      Gr[2][pa] += d; Gr[2][pb] -= d;
+      for (const [j, w] of deckVec(A, dA)) Gr[3][j] += d * w;
+      for (const [j, w] of deckVec(B, dB)) Gr[3][j] -= d * w;
+      const ta = teamVec(A, dA), tb = teamVec(B, dB);
+      for (let k = 0; k < ta.length; k++) Gr[4][k] += dT * (ta[k] - tb[k]);
+    }
+    const c1 = 1 - 0.9 ** it, c2 = 1 - 0.999 ** it;
+    for (let k = 0; k < P.length; k++) {
+      const a = P[k], g = Gr[k], m = Mm[k], v = Vv[k];
+      for (let j = 0; j < a.length; j++) {
+        const gg = g[j] + 2 * L[k] * a[j];
+        m[j] = 0.9 * m[j] + 0.1 * gg; v[j] = 0.999 * v[j] + 0.001 * gg * gg;
+        a[j] -= 0.03 * (m[j] / c1) / (Math.sqrt(v[j] / c2) + 1e-8);
+      }
+    }
+  }
+  const nb = new Float64Array(mons.length);
+  for (const [A, B] of games) for (const t of [A, B]) for (const j of tf[t].f) nb[j]++;
+  for (let j = 0; j < b.length; j++) b[j] *= nb[j] / (nb[j] + 1000);
+  return {b, Fm, s, c, T, x, predictLogit: (A, B, dA, dB) => x(A, dA) - x(B, dB)};
+}

+// IDEA 2 (--idea=matchup): Blade-Chest Intransitive Team-vs-Team Matchup Term (Chen & Joachims 2016).
+// Adds antisymmetric low-rank matchup term: u(A).v(B) - u(B).v(A) on top of baseline x(A) - x(B).
+function fitMatchup(data, ctx, games, D = 4, lbc = 15) {
+  const base = fitBaseline(data, ctx, games);
+  const {evDates} = data;
+  const {mons, tf, nP} = ctx;
+  const half = data.S.half ?? 14;
+  const rng = makeRng(99);
+  const U = new Float64Array(mons.length * D), Vc = new Float64Array(mons.length * D);
+  for (let i = 0; i < U.length; i++) { U[i] = (rng() - 0.5) * 0.03; Vc[i] = (rng() - 0.5) * 0.03; }
+  const P = [U, Vc], Mm = P.map(a => new Float64Array(a.length)), Vv = P.map(a => new Float64Array(a.length));
+
+  let last = -Infinity; for (const g of games) last = Math.max(last, dayNum(evDates[g[3]]));
+  const W = games.map(g => half ? Math.pow(0.5, (last - dayNum(evDates[g[3]])) / half) : 1);
+  const Wn = games.length / (W.reduce((a, x) => a + x, 0) || 1);
+  const baseEta = games.map(([A, B, , , pa, pb, , dA, dB]) => base.x(A, dA) - base.x(B, dB) + base.s[pa] - base.s[pb]);
+
+  const bcDot = (A, B) => {
+    let val = 0;
+    for (let d = 0; d < D; d++) {
+      let uA = 0, vA = 0, uB = 0, vB = 0;
+      for (const j of tf[A].f) { uA += U[j * D + d]; vA += Vc[j * D + d]; }
+      for (const j of tf[B].f) { uB += U[j * D + d]; vB += Vc[j * D + d]; }
+      val += (uA * vB - uB * vA) / 6;
+    }
+    return val;
+  };
+
+  const bcIters = Math.min(150, ITERS);
+  for (let it = 1; it <= bcIters; it++) {
+    const gU = new Float64Array(U.length), gV = new Float64Array(Vc.length);
+    for (let gi = 0; gi < games.length; gi++) {
+      const [A, B, r] = games[gi];
+      const e0 = sig(baseEta[gi] + bcDot(A, B)) - r, dW = (e0 * W[gi] * Wn) / 6;
+      for (let d = 0; d < D; d++) {
+        let uA = 0, vA = 0, uB = 0, vB = 0;
+        for (const j of tf[A].f) { uA += U[j * D + d]; vA += Vc[j * D + d]; }
+        for (const j of tf[B].f) { uB += U[j * D + d]; vB += Vc[j * D + d]; }
+        for (const j of tf[A].f) { gU[j * D + d] += dW * vB; gV[j * D + d] -= dW * uB; }
+        for (const j of tf[B].f) { gU[j * D + d] -= dW * vA; gV[j * D + d] += dW * uA; }
+      }
+    }
+    const c1 = 1 - 0.9 ** it, c2 = 1 - 0.999 ** it;
+    for (const [k, gr] of [[0, gU], [1, gV]]) {
+      const a = P[k], m = Mm[k], v = Vv[k];
+      for (let j = 0; j < a.length; j++) {
+        const gg = gr[j] + 2 * lbc * a[j];
+        m[j] = 0.9 * m[j] + 0.1 * gg; v[j] = 0.999 * v[j] + 0.001 * gg * gg;
+        a[j] -= 0.02 * (m[j] / c1) / (Math.sqrt(v[j] / c2) + 1e-8);
+      }
+    }
+  }
+  return {
+    ...base, U, Vc,
+    predictLogit: (A, B, dA, dB) => base.x(A, dA) - base.x(B, dB) + bcDot(A, B),
+  };
+}

+// IDEA 3 (--idea=glicko): Strictly Causal Pre-Match Glicko-2 Player Skill Offset (Glickman 2013).
+// Computes chronological player skill (mu, phi) BEFORE each game with RD inflation over inactive days,
+// then fits team strength with that dynamic skill offset + lightly shrunk residual player skill.
+function computeCausalGlickoOffsets(data, games) {
+  const {evDates, M} = data;
+  const order = games.map((g, i) => ({g, i, d: dayNum(evDates[g[3]])})).sort((a, b) => a.d - b.d || a.g[6] - b.g[6]);
+  const mu = new Float64Array(M.players);
+  const phi = new Float64Array(M.players).fill(1.2); // initial RD in logit-like scale
+  const lastDay = new Float64Array(M.players).fill(-1e9);
+  const offsets = new Float64Array(games.length);
+  const cDrift = 0.045; // RD inflation per sqrt(day) of inactivity
+
+  for (const {g, i, d} of order) {
+    const [, , r, , pa, pb] = g;
+    for (const p of [pa, pb]) {
+      if (lastDay[p] > -1e8 && d > lastDay[p]) {
+        phi[p] = Math.min(1.5, Math.hypot(phi[p], cDrift * Math.sqrt(d - lastDay[p])));
+      }
+    }
+    // Pre-match skill difference (strictly causal: uses ONLY prior games)
+    offsets[i] = 0.5 * (mu[pa] - mu[pb]);
+
+    // Glicko-style Bayesian update after observing result r
+    const gPhi = ph => 1 / Math.sqrt(1 + (3 * ph * ph) / (Math.PI * Math.PI));
+    const gB = gPhi(phi[pb]), gA = gPhi(phi[pa]);
+    const eA = sig(gB * (mu[pa] - mu[pb]));
+    const eB = 1 - eA;
+    const vA = 1 / Math.max(1e-6, gB * gB * eA * (1 - eA));
+    const vB = 1 / Math.max(1e-6, gA * gA * eB * (1 - eB));
+    const phiA2 = 1 / (1 / (phi[pa] * phi[pa]) + 1 / vA);
+    const phiB2 = 1 / (1 / (phi[pb] * phi[pb]) + 1 / vB);
+    mu[pa] += phiA2 * gB * (r - eA);
+    mu[pb] += phiB2 * gA * ((1 - r) - eB);
+    phi[pa] = Math.sqrt(phiA2);
+    phi[pb] = Math.sqrt(phiB2);
+    lastDay[pa] = d;
+    lastDay[pb] = d;
+  }
+  return offsets;
+}
+
+function fitGlicko(data, ctx, games) {
+  const offsets = computeCausalGlickoOffsets(data, games);
+  // With causal dynamic skill already explaining drift, use stronger ridge on residual static skill.
+  return fitBaseline(data, ctx, games, {skillOffset: offsets, ls: (1.5 * (data.S.shrink ?? 3)) * 3});
+}

+// IDEA 4 (--idea=no-evid-hier): Remove Post-Hoc EVID_K Double Shrinkage + Recency-Aligned Team-Aware Six Deviation.
+// Replaces post-hoc b *= n/(n+1000) with clean in-objective ridge (lb * 2.5, lp * 2, evidK=0, evidKp=0),
+// and adds a recency-weighted, team-basics-aware exact-six residual delta (fixing six.mjs Part E #2).
+function fitNoEvidHier(data, ctx, games) {
+  const K = data.S.shrink ?? 3;
+  const base = fitBaseline(data, ctx, games, {
+    lb: 4 * K * 2.5,
+    lp: 15 * K * (data.S.pairShrink ?? 4) * 1.5,
+    evidK: 0,
+    evidKp: 0,
+  });
+  // Recency-weighted exact-six deviation delta (tau = 0.1) with FULL base.x (including team basics!).
+  const {evDates, M} = data;
+  const half = data.S.half ?? 14;
+  let last = -Infinity; for (const g of games) last = Math.max(last, dayNum(evDates[g[3]]));
+  const W = games.map(g => half ? Math.pow(0.5, (last - dayNum(evDates[g[3]])) / half) : 1);
+  const Wn = games.length / (W.reduce((a, x) => a + x, 0) || 1);
+  const dl = new Float64Array(M.teams.length), md = new Float64Array(M.teams.length), vd = new Float64Array(M.teams.length);
+  const tau2 = 0.1 * 0.1;
+  const baseX = games.map(g => [base.x(g[0], g[7]), base.x(g[1], g[8])]);
+  for (let it = 1; it <= 120; it++) {
+    const gd = new Float64Array(M.teams.length);
+    for (let i = 0; i < games.length; i++) {
+      const g = games[i];
+      const eta = baseX[i][0] + dl[g[0]] - baseX[i][1] - dl[g[1]] + base.s[g[4]] - base.s[g[5]];
+      const e = (sig(eta) - g[2]) * W[i] * Wn;
+      gd[g[0]] += e; gd[g[1]] -= e;
+    }
+    const c1 = 1 - 0.9 ** it, c2 = 1 - 0.999 ** it;
+    for (let j = 0; j < dl.length; j++) {
+      if (!gd[j] && !dl[j]) continue;
+      const gr = gd[j] + dl[j] / tau2;
+      md[j] = 0.9 * md[j] + 0.1 * gr; vd[j] = 0.999 * vd[j] + 0.001 * gr * gr;
+      dl[j] -= 0.04 * (md[j] / c1) / (Math.sqrt(vd[j] / c2) + 1e-8);
+    }
+  }
+  const ng = new Int32Array(M.teams.length);
+  for (const g of games) { ng[g[0]]++; ng[g[1]]++; }
+  for (let j = 0; j < dl.length; j++) if (ng[j] < 10) dl[j] = 0;
+  return {
+    ...base, dl,
+    predictLogit: (A, B, dA, dB) => (base.x(A, dA) + dl[A]) - (base.x(B, dB) + dl[B]),
+  };
+}

+// IDEA 5 (--idea=mega-cap): Champions Rule 1-Mega-Per-Battle Diminishing Returns (multiMega team feature).

+  return fitBaseline(data, ctx, games);

+// ============================================================================
+// 4. METRICS & TOURNAMENT-CLUSTERED PAIRED 95% BOOTSTRAP CI
+// ============================================================================
+function metricsOf(probs, ys) {
+  const n = probs.length;
+  if (!n) return {n: 0, acc: NaN, ll: NaN, brier: NaN, calSlope: NaN, unknown: true};
+  let acc = 0, ll = 0, brier = 0;
+  const logits = [];
+  for (let i = 0; i < n; i++) {
+    const p = Math.min(1 - 1e-9, Math.max(1e-9, probs[i])), y = ys[i];
+    if ((p > 0.5) === (y === 1)) acc++;
+    ll -= y ? Math.log(p) : Math.log(1 - p);
+    brier += (p - y) * (p - y);
+    logits.push([Math.log(p / (1 - p)), y]);
+  }
+  // Calibration slope via Newton on log-odds
+  let w = 1;
+  for (let k = 0; k < 25; k++) {
+    let g = 0, h = 0;
+    for (const [e, y] of logits) { const q = sig(w * e); g += (q - y) * e; h += q * (1 - q) * e * e; }
+    w -= g / (h || 1);
+    if (!Number.isFinite(w) || Math.abs(w) > 20) { w = 1; break; }
+  }
+  return {n, acc: acc / n, ll: ll / n, brier: brier / n, calSlope: w, unknown: n < 500};
+}
+
+// Tournament-clustered bootstrap: resamples whole events (preserving within-tournament correlation).
+function bootstrapCI(probs, ys, evs, baseProbs = null, boots = BOOTS) {
+  const byEv = new Map();
+  for (let i = 0; i < probs.length; i++) {
+    let a = byEv.get(evs[i]); if (!a) byEv.set(evs[i], a = []);
+    a.push(i);
+  }
+  const evList = [...byEv.values()];
+  if (evList.length < 2) return null;
+  const rng = makeRng(20261125);
+  const accs = [], lls = [], briers = [], dAcc = [], dLl = [], dBrier = [];
+
+  for (let b = 0; b < boots; b++) {
+    let n = 0, a1 = 0, l1 = 0, br1 = 0, a0 = 0, l0 = 0, br0 = 0;
+    for (let k = 0; k < evList.length; k++) {
+      const idxs = evList[Math.floor(rng() * evList.length)];
+      for (const i of idxs) {
+        const y = ys[i], p = Math.min(1 - 1e-9, Math.max(1e-9, probs[i]));
+        n++;
+        if ((p > 0.5) === (y === 1)) a1++;
+        l1 -= y ? Math.log(p) : Math.log(1 - p);
+        br1 += (p - y) * (p - y);
+        if (baseProbs) {
+          const p0 = Math.min(1 - 1e-9, Math.max(1e-9, baseProbs[i]));
+          if ((p0 > 0.5) === (y === 1)) a0++;
+          l0 -= y ? Math.log(p0) : Math.log(1 - p0);
+          br0 += (p0 - y) * (p0 - y);
+        }
+      }
+    }
+    accs.push(a1 / n); lls.push(l1 / n); briers.push(br1 / n);
+    if (baseProbs) { dAcc.push((a1 - a0) / n); dLl.push((l1 - l0) / n); dBrier.push((br1 - br0) / n); }
+  }
+  const pct = arr => {
+    arr.sort((x, y) => x - y);
+    return [arr[Math.floor(0.025 * arr.length)], arr[Math.floor(0.975 * arr.length)]];
+  };
+  return {
+    accCI: pct(accs), llCI: pct(lls), brierCI: pct(briers),
+    dAccCI: baseProbs ? pct(dAcc) : null,
+    dLlCI: baseProbs ? pct(dLl) : null,
+    dBrierCI: baseProbs ? pct(dBrier) : null,
+  };
+}

+  if (!tourDates.length) throw new Error('No tournament events found in matches.json');

+    const rowLine = [`  cut ${cut}->${to} (n=${test.length}${test.length < 500 ? ' UNKNOWN' : ''}):`];
+

+      const probs = test.map(fitted.predictProb);
+      const m = metricsOf(probs, ys);

+      pooled[v.id].ys.push(...ys);

+      rowLine.push(`${v.id} acc=${(m.acc * 100).toFixed(1)}% ll=${m.ll.toFixed(4)}`);
+    }
+    console.log(rowLine.join(' | '));
+  }
+
+  console.log('\n=== POOLED WALK-FORWARD RESULTS (PAIRED ON EXACT SAME GAMES) ===');
+  const baseP = pooled.baseline;
+  const summary = {};
+  for (const v of variants) {

+      else if (ci && ci.dLlCI[0] > 0) verdict = 'REJECT (95% CI strictly worse than baseline)';
+      else verdict = 'NO DIFFERENCE / REJECT (95% CI crosses 0)';

+    const fCI = c => c ? `[${c[0].toFixed(4)}, ${c[1].toFixed(4)}]` : 'n/a';
+    const fPctCI = c => c ? `[${(c[0] * 100).toFixed(2)}%, ${(c[1] * 100).toFixed(2)}%]` : 'n/a';

+    console.log(`  games=${m.n}${m.unknown ? ' (UNKNOWN)' : ''} | acc=${(m.acc * 100).toFixed(2)}% ${ci ? fPctCI(ci.accCI) : ''} | ll=${m.ll.toFixed(5)} ${ci ? fCI(ci.llCI) : ''} | brier=${m.brier.toFixed(5)} ${ci ? fCI(ci.brierCI) : ''} | calSlope=${m.calSlope.toFixed(3)}`);
+    if (ci && ci.dLlCI) {
+      const bm = metricsOf(baseP.probs, baseP.ys);
+      console.log(`  delta vs baseline: dAcc=${((m.acc - bm.acc) * 100 >= 0 ? '+' : '')}${((m.acc - bm.acc) * 100).toFixed(2)} pts ${fPctCI(ci.dAccCI)} | dLL=${(m.ll - bm.ll >= 0 ? '+' : '')}${(m.ll - bm.ll).toFixed(5)} ${fCI(ci.dLlCI)} | dBrier=${(m.brier - bm.brier >= 0 ? '+' : '')}${(m.brier - bm.brier).toFixed(5)} ${fCI(ci.dBrierCI)}`);
+    }
+  }
+  return summary;
+}

+// ============================================================================
+// 6. PART D: M-D DAY ONE SMALL-DATA SIMULATION (WEEKS 1-4 -> TEST WEEK 5+)
+// ============================================================================
+function runMdDayOneSim(data) {
+  const {evDates, isSD, G} = data;
+  const dates = data.M.events.map((e, i) => isSD(i) ? null : e[1]).filter(Boolean).sort();
+  const start = dates[0];
+  const w4End = addDays(start, 28);
+  const testGames = G.filter(g => evDates[g[3]] > w4End && !isSD(g[3]));
+  console.log(`\n=== PART D: M-D DAY-ONE SMALL-DATA SIMULATION (start=${start}, test > ${w4End}, testGames=${testGames.length}${testGames.length < 500 ? ' UNKNOWN' : ''}) ===`);
+  if (!testGames.length) { console.log('  Not enough date span (>4 weeks) to run M-D day-one simulation.'); return null; }
+
+  // Simulated "prior regulation" vector: fit on the FULL dataset with 35% random Gaussian noise to mimic a balance-patch shift
+  // (only used to benchmark L2-SP transfer decay vs cold start; never touches test labels directly when run with a real M-C prior file).
+  const fullCtx = buildContext(data, G.filter(g => evDates[g[3]] <= w4End));
+  const rng = makeRng(777);
+  const ys = testGames.map(g => g[2] === 1 ? 1 : 0);
+  const evs = testGames.map(g => String(g[3]));
+
+  const out = [];
+  for (const wk of [1, 2, 3, 4]) {
+    const cut = addDays(start, 7 * wk);
+    const tr = G.filter(g => evDates[g[3]] <= cut);
+    if (tr.length < 30) { console.log(`  Week ${wk} (<= ${cut}): only ${tr.length} train games (skipped)`); continue; }
+
+    // Strategy 1: Cold start (today's model.mjs settings)
+    const cold = fitWithCalib(data, tr, (d, c, gs) => fitBaseline(d, c, gs));
+    const pCold = testGames.map(cold.predictProb);
+    const mCold = metricsOf(pCold, ys);
+
+    // Strategy 2: Heavy-shrinkage species-only (3x ridge, no pairs/sets until data accumulates)
+    const heavy = fitWithCalib(data, tr, (d, c, gs) => fitBaseline(d, c, gs, {lb: 4 * 9, usePairs: false, useSets: false, evidK: 300}));
+    const pHeavy = testGames.map(heavy.predictProb);
+    const mHeavy = metricsOf(pHeavy, ys);
+
+    // Strategy 3: Usage log-prior (shrinks each mon toward alpha * log(usage_i / mean_usage) from new-reg usage)
+    const usageModel = fitWithCalib(data, tr, (d, c, gs) => {
+      const cnt = new Float64Array(c.mons.length);
+      for (const [A, B] of gs) for (const t of [A, B]) for (const j of c.tf[t].f) cnt[j]++;
+      const meanU = (cnt.reduce((a, x) => a + x, 0) || 1) / Math.max(1, c.mons.length);
+      const priorB = Float64Array.from(cnt, x => 0.12 * Math.log((x + 5) / (meanU + 5)));
+      return fitBaseline(d, c, gs, {usePairs: false, useSets: false, priorB, priorLam: 12, evidK: 300});
+    });
+    const pUsage = testGames.map(usageModel.predictProb);
+    const mUsage = metricsOf(pUsage, ys);
+
+    // Strategy 4: L2-SP Transfer Prior with decaying weight lambda_sp = 25 / (1 + tr.length / 2500)
+    // Uses week-1 usage-anchored prior + simulated noisy prior if no external --prior-model=out/model_mc.json is given.
+    const priorPath = arg('prior-model', '');
+    let extPrior = null;
+    if (priorPath && fs.existsSync(priorPath)) extPrior = JSON.parse(fs.readFileSync(priorPath, 'utf8')).mons || null;
+    const l2sp = fitWithCalib(data, tr, (d, c, gs) => {
+      const priorB = new Float64Array(c.mons.length);
+      if (extPrior) {
+        for (let j = 0; j < c.mons.length; j++) priorB[j] = extPrior[c.mons[j]] || 0;
+      } else {
+        // Fallback self-contained prior from week-1 raw win rates shrunk strongly (keeps simulation strictly causal).
+        const w = new Float64Array(c.mons.length), g = new Float64Array(c.mons.length);
+        for (const [A, B, r] of tr) { for (const j of c.tf[A].f) { w[j] += r; g[j]++; } for (const j of c.tf[B].f) { w[j] += 1 - r; g[j]++; } }
+        for (let j = 0; j < c.mons.length; j++) priorB[j] = 0.25 * Math.log((w[j] + 15) / (g[j] - w[j] + 15));
+      }
+      const lam = 25 / (1 + gs.length / 2500);
+      return fitBaseline(d, c, gs, {usePairs: gs.length >= 1500, useSets: gs.length >= 2500, priorB, priorLam: lam, evidK: 300});
+    });
+    const pL2sp = testGames.map(l2sp.predictProb);
+    const mL2sp = metricsOf(pL2sp, ys);
+
+    const ciH = bootstrapCI(pHeavy, ys, evs, pCold);
+    const ciU = bootstrapCI(pUsage, ys, evs, pCold);
+    const ciL = bootstrapCI(pL2sp, ys, evs, pCold);
+    console.log(`  Week ${wk} (train=${tr.length} games <= ${cut}):`);
+    console.log(`    cold-start : acc=${(mCold.acc * 100).toFixed(2)}% ll=${mCold.ll.toFixed(5)} brier=${mCold.brier.toFixed(5)} cal=${mCold.calSlope.toFixed(3)}`);
+    console.log(`    heavy-ridge: acc=${(mHeavy.acc * 100).toFixed(2)}% ll=${mHeavy.ll.toFixed(5)} dLL=${(mHeavy.ll - mCold.ll).toFixed(5)} ${ciH ? `[${ciH.dLlCI[0].toFixed(5)}, ${ciH.dLlCI[1].toFixed(5)}]` : ''}`);
+    console.log(`    usage-prior: acc=${(mUsage.acc * 100).toFixed(2)}% ll=${mUsage.ll.toFixed(5)} dLL=${(mUsage.ll - mCold.ll).toFixed(5)} ${ciU ? `[${ciU.dLlCI[0].toFixed(5)}, ${ciU.dLlCI[1].toFixed(5)}]` : ''}`);
+    console.log(`    l2-sp-decay: acc=${(mL2sp.acc * 100).toFixed(2)}% ll=${mL2sp.ll.toFixed(5)} dLL=${(mL2sp.ll - mCold.ll).toFixed(5)} ${ciL ? `[${ciL.dLlCI[0].toFixed(5)}, ${ciL.dLlCI[1].toFixed(5)}]` : ''}`);
+    out.push({week: wk, cut, trainGames: tr.length, cold: mCold, heavy: mHeavy, usage: mUsage, l2sp: mL2sp});
+  }
+  return out;
+}

+// ============================================================================
+// 7. BASELINE REPRODUCTION CHECK (--verify-baseline)
+// ============================================================================
+function verifyBaselineRepro(data) {
+  const {evDates, G} = data;
+  const order = [...evDates.keys()].sort((a, b) => evDates[a] < evDates[b] ? -1 : 1);
+  const lo = Math.floor(order.length * 0.8);
+  const before = new Set(order.slice(0, lo)), cut = new Set(order.slice(lo));
+  const train = G.filter(g => before.has(g[3])), test = G.filter(g => cut.has(g[3]));
+  // Use full-G context ONLY in this check to match model.mjs's current exact behavior for bit-level verification.
+  const ctx = buildContext(data, G);
+  const m = fitBaseline(data, ctx, train);
+  const ys = test.map(g => g[2] === 1 ? 1 : 0);
+  const rawProbs = test.map(g => sig(m.predictLogit(g[0], g[1], g[7], g[8])));
+  const calSlope = fitCalib(m, test);
+  const calProbs = test.map(g => sig(calSlope * m.predictLogit(g[0], g[1], g[7], g[8])));
+  const mr = metricsOf(rawProbs, ys), mc = metricsOf(calProbs, ys);
+  console.log(`\n=== BASELINE REPRODUCTION CHECK (same 80/20 split as model.mjs) ===`);
+  console.log(`  train=${train.length} test=${test.length} | raw: acc=${(mr.acc * 100).toFixed(2)}% ll=${mr.ll.toFixed(4)} | calibrated (slope=${calSlope.toFixed(3)}): ll=${mc.ll.toFixed(4)}`);
+  console.log(`  Compare directly against: FAST=${data.S.shrink ?? 3},${data.S.half ?? 14},${data.S.skill ?? 1},${data.S.sets ?? 60} node model.mjs`);
+}
