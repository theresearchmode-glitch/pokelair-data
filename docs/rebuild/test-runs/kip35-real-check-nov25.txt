DIFFERENCES, Kip's baseline (experiments/kip35-zero-center-eb.mjs) vs model.mjs:
 1. Training steps: Kip 160 (kip:28 ITERS default) vs model.mjs 250 (model.mjs:95). Biggest suspect.
 2. protectLow: Kip counts Pokemon with any Protect-family move (Protect, Detect, Spiky Shield, King's Shield, Baneful Bunker, Silk Trap,
    Burning Bulwark, Obstruct; kip:44-66). Real team-basics.mjs:22 counts only ":Protect". On the 12,823 sheets in games:
    protectLow = 1 on 749 sheets (Kip) vs 1,246 (real); 497 sheets differ.
 3. Scoring: Kip scores raw in-memory x (kip:305). The page and this check use the shipped model: sets clamped to setRange
    (model.mjs:204-210, 221-222), pairs shipped only if |q| >= .005 (model.mjs:236), numbers rounded to 4 places.
 4. Calibration: Kip fits a bounded Newton (step +-0.5, slope 0.1..2.5; kip:238-252) on the newest 20% of events that have games,
    with a model trained on the other 80%. model.mjs fits unbounded Newton (model.mjs:198-199) on the newest 20% of ALL events in the
    file (model.mjs:67-74), with `full` trained on the older 80%. Calib values came out close (e.g. last window .759 Kip vs .770 real).
 5. Ship gate: model.mjs ships only if it beats raw win rates (model.mjs:189); Kip has none. All 4 windows shipped, so no effect there;
    it matters in the week-1 test (below).
 6. Same in both (checked by reading): pairs >= 30 teams (model.mjs:27-30 vs kip:72-86; teams are stored sorted, 0 of 7,583 unsorted,
    so Kip's sorted key = the real key), sets >= 40 decks (model.mjs:36-39 vs kip:101-106), centering within species
    (model.mjs:41-44 vs kip:108-123), noMega (model.mjs:65 vs kip:171), lb 40 / lp 150*pairShrink 4 = 600 / ls 15 / lc 60
    (model-settings.json shrink 10, sets 60, pairShrink 4; model.mjs:150-161, 100), half 14, teamHalf 0 (model-settings.json),
    evidK 1000 / evidKp 300 (model.mjs:85, 129-132 vs kip:225-226), Adam .9/.999/lr .03 (model.mjs:119-121 vs kip:206-213),
    player skill on, sets always on (with locked FAST settings `species` is null, so useSets is always true: model.mjs:164-175).
